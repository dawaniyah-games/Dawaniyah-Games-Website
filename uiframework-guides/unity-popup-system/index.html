How to Build a Popup System in Unity (Without SetActive)

By Mohamed Moghazi · Unity 2022.3 to Unity 6 · UGUI · about 8 minutes

Short answer: treat every popup as a state on a stack. Showing a popup pushes it on top of the current screen; closing it pops it off. With the free UI Framework for Unity that is two calls: await UiManager.ShowState<MyPopupUiState>(data, additive: true) to open and await UiManager.HideUI() to close.

This guide builds a confirm-purchase popup that opens over a store screen, shows the item and price it is given, closes from its own buttons and from the Android Back button, and can stack with other popups.

Why SetActive popups break

The usual first version keeps every popup in the scene and toggles it with SetActive(true). It works for one popup and decays as the game grows:

  • Nothing knows the order. Two popups open, the player presses Back, and the wrong one closes.
  • Sort orders are picked by feel. A new popup shows behind the store because its canvas order was never set.
  • Data leaks between opens. The popup still shows the last item because nothing resets it.
  • Everything is loaded at boot. Every popup sits in memory whether or not it ever opens.

A popup system fixes all four with one idea: a stack of states. The top of the stack is what the player is looking at, Back always means "pop the top", and each popup gets its data handed in when it opens.

What a popup system needs

NeedHow a state stack handles it
Open on top of any screenPush the popup state additively; the screen below stays loaded and visible
Close the right onePop the top of the stack
Pass dataHand an object to the popup when it opens
Draw above screensA higher canvas sorting order on the popup
Use memory only when openLoad the popup on open, unload it on close
Animate in and outShow and hide animations per popup

Build it with UI Framework, step by step

If the package isn't installed yet, follow Get started first (Package Manager → Add package from git URL, then create the config). It takes about two minutes.

1. Create the popup element

Open Window → UI Framework → UI Setup Manager → Elements and create ConfirmPurchaseUiElement with Include Parameters Class ticked. The editor generates the script, a params class and the popup's own scene. Build the popup under Root: a dimmed full-screen backdrop (an Image that blocks clicks) and a panel with the item name, price, and Cancel and Buy buttons.

In the element's Canvas settings, set the sorting order above your screens, so the popup always draws on top. Pick a show animation such as Scale and a hide animation such as Fade.

2. Give it data

The generated params class holds what the popup shows:

using UiFramework.Core;

public class ConfirmPurchaseUiElementParams : UiPopulationParams
{
    public string ItemName;
    public int Price;
}

The element reads it in Populate, which runs every time the popup opens. Keep it idempotent: set values, don't append to them.

using System;
using TMPro;
using UiFramework.Core;
using UiFramework.Runtime.Manager;
using UnityEngine;

public class ConfirmPurchaseUiElement : UiElement
{
    [SerializeField] private TMP_Text itemNameText;
    [SerializeField] private TMP_Text priceText;

    public override void Populate(object context = null)
    {
        base.Populate(context);

        ConfirmPurchaseUiElementParams data = context as ConfirmPurchaseUiElementParams;
        if (data == null)
        {
            return;
        }

        itemNameText.text = data.ItemName;
        priceText.text = data.Price.ToString();
    }

    // Hook the Cancel button's OnClick to this in the Inspector.
    public async void OnCancelClicked()
    {
        try
        {
            await UiManager.HideUI();
        }
        catch (Exception exception)
        {
            Debug.LogError("[ConfirmPurchase] Close failed: " + exception);
        }
    }
}

3. Make it a state

In the States tab, create ConfirmPurchaseUiState containing only the popup's scene, then press Build Runtime UiConfig. A popup state contains just the popup; the screen it opens over is already on the stack.

4. Open it from the store

ConfirmPurchaseUiElementParams purchase = new ConfirmPurchaseUiElementParams();
purchase.ItemName = "Neon Blade";
purchase.Price = 250;

// additive: true pushes the popup on top; the store stays loaded and visible.
await UiManager.ShowState<ConfirmPurchaseUiState>(purchase, additive: true);

Without additive: true, ShowState replaces the whole stack, which is what you want for moving between screens, not for popups.

5. Close it, including with Back

HideUI() pops the top state: it plays the popup's hide animation and unloads its scene, and the store underneath is untouched. For the Android Back button, close only when the popup is actually on top:

if (UiManager.IsLastSceneActive<ConfirmPurchaseUiState>())
{
    await UiManager.HideUI();
}

6. Stack popups

A popup can open another popup, for example a "Not enough coins" notice from the purchase popup. Each additive state goes on top of the last, and each HideUI() closes the newest one, so they always close in the reverse order they opened.

Common mistakes

  • The popup replaces the screen instead of covering it. You left out additive: true.
  • "No UI state key registered". The state class name must equal the state key exactly, and Build Runtime UiConfig must run after you create the state.
  • The popup shows behind the store. Raise its canvas sorting order in the element's Canvas settings.
  • Two fast taps open or close the wrong thing. Calls aren't queued for you. Await each call, or route navigation through one place that queues calls, as the showcase app's ShowcaseNavigator does.
  • Old data flashes on open. Set every field in Populate, every time.

FAQ

How do I pass data to a Unity popup?

Pass an object as the context of ShowState. The popup reads it in Populate(object context) with context as YourParams.

Does the screen under the popup keep running?

Yes. An additive state leaves the states below loaded and on screen; the popup's backdrop blocks clicks to them.

Can I override the popup's animation for one call?

Yes: pass a transition, for example transition: UiTransition.ShowWith(TweenPresets.SlideUpKey), to ShowState, or UiTransition.HideWith(...) to HideUI.
